## Summary

The kunskapsträd page (`trad.astro`) is a self-contained 636-line Astro file that renders 6 SVG trees (one per skill domain) for Kurs B only, with a shared radar chart. All interactivity (click/keyboard leaf toggle, pop animation, crown glow, branch coloring, progress bar, radar update) is in a single `<script>` tag referencing a hardcoded `STORAGE_KEY = "sfi-checklist-B"`.

Expanding to three courses requires: (1) building data pipelines for C and D identical to the existing B pipeline, (2) rendering 3×6=18 SVG trees grouped into per-course panels, (3) implementing client-side tab switching identical in pattern to `index.astro`, (4) making the JS multi-course aware so storage keys and DOM selectors are scoped per course, and (5) introducing SVG parameter sets (trunk width, crown radius, root count, leaf orbit radii, arc spread) that visually differentiate sapling/medium/full trees.

The good news: all data is already available (`kurs-c.json`, `kurs-d.json` exist), all patterns are established (tab switching in `index.astro`, localStorage per course in `index.astro`), and the entire implementation is in one file that can be directly modified.

**Primary recommendation:** Refactor `trad.astro` to (a) build `treesData` for all three courses at build time, (b) render three course panels with show/hide tab switching, (c) make the client script multi-course aware with per-course storage keys, and (d) drive tree SVG visual variation via a per-tier parameter object passed to `computePositions` and the trunk/root/crown SVG paths.

## Architecture Patterns

### Pattern 1: Build-Time Data Pipeline (replicate from B to C and D)

**What:** Import all three course JSON files at the top of the frontmatter, build a `skills` array for each, then `treesData` array for each.

**Current B-only pattern** [VERIFIED: trad.astro lines 1-123]:

```typescript
// Frontmatter
import kursB from "../data/kurs-b.json";
const skills = [ { id: "hora", goals: kursB.domains.horforstaelse.goals, ... }, ... ];
const treesData = skills.map(skill => ({ ...skill, leaves: computePositions(...) }));
```

**Extended pattern for all three courses:**

```typescript
import kursB from "../data/kurs-b.json";
import kursC from "../data/kurs-c.json";
import kursD from "../data/kurs-d.json";

function buildSkills(kursData, coursePrefix) {
  return [
    { id: "hora", label: "Höra", ..., goals: kursData.domains.horforstaelse.goals },
    { id: "tala", label: "Tala", ..., goals: [
        ...kursData.domains["muntlig-interaktion"].goals,
        ...kursData.domains["muntlig-produktion"].goals,
```

### Pattern 4: Multi-Course JavaScript State

**What:** The current script hardcodes `STORAGE_KEY = "sfi-checklist-B"`. For multi-course, the script must:

1. Track `activeCourse` variable (default `"B"`)
2. Load/save using `sfi-checklist-${activeCourse}`
3. On tab switch: save nothing (state persists from prior loads), show the correct panel, reinitialize leaf visuals for the newly visible course

**Key decision from CONTEXT.md D-03:** All three courses' localStorage keys are already written by `index.astro`. The tree page reads from the same keys. On page load, initialize ALL three courses' leaf states (not just the active one), because:
- The user may have checked items on `index.astro` before navigating to the tree
- Switching tabs should instantly reflect correct state without re-loading from localStorage on every switch

**Recommended JS initialization approach:**

```javascript
const COURSES = ["B", "C", "D"];
const states = {};
COURSES.forEach(course => {
  states[course] = loadState(course); // reads sfi-checklist-{course}
});

// Init all panels' leaves from state
COURSES.forEach(course => {
  document.querySelectorAll(`#tree-panel-${course} .leaf-node`).forEach(leaf => {
    if (states[course][leaf.dataset.goalId]) {
      setLeafChecked(leaf, true);
    }
  });
  updateAllProgress(course);
  updateAllCrowns(course);
  updateRadar(course);
});
```

### Pattern 5: Per-Course Radar Chart

**What:** One radar per course (D-08/D-09). Three radar SVGs exist in HTML — one inside each panel. Radar IDs must be course-scoped: `radar-B`, `radar-polygon-B`, `radar-dot-hora-B`, `pct-hora-B`, etc.

**Current:** Single `id="radar"`, `id="radar-polygon"`, `id="radar-dot-{skillId}"`, `id="pct-{skillId}"`
**Extended:** Prefix with course: `id="radar-B"`, `id="radar-polygon-B"`, `id="radar-dot-hora-B"`, `id="pct-hora-B"`

The `updateRadar(course)` function uses `skillsClient[course]` and targets course-scoped element IDs.

### Pattern 6: Goal Text Panel — Course Scoping

**What:** Each tree card has a `[data-goal-panel="{skillId}"]` element. With 18 trees, skill IDs are NOT unique across courses — all courses have `hora`, `lasa`, etc. The selector must be scoped to the active course panel.

**Fix:** Add `data-course` to goal panel and tree card: `data-goal-panel="${course}-${skill.id}"`. Or: scope DOM queries to `#tree-panel-${course}`.

Scoping DOM queries to the active panel container is simpler and requires no change to panel markup:

```javascript
function showGoalText(course, skillId, goalId, isChecked) {
  const panel = document.querySelector(`#tree-panel-${course} [data-goal-panel="${skillId}"]`);
  // ...
}
```

## Common Pitfalls

### Pitfall 1: Non-unique DOM IDs across courses
**What goes wrong:** `id="radar-polygon"` appears three times in the DOM (once per course panel). `document.getElementById` returns the first match, so C and D radars never update.
**Why it happens:** Copy-paste of Kurs B panel markup without scoping IDs.
**How to avoid:** Course-prefix all IDs: `id="radar-polygon-B"`, `id="radar-polygon-C"`, `id="radar-polygon-D"`. The `updateRadar(course)` function uses `document.getElementById(`radar-polygon-${course}`)`.
**Warning signs:** Radar visually works only on B tab; switching to C or D shows stale/empty radar.

### Pitfall 2: Crown glow gradient ID collision
**What goes wrong:** Each tree SVG has `<radialGradient id="crown-{skillId}">`. With 3 courses × 6 skills = 18 gradient defs, `id="crown-hora"` appears three times (one per course SVG). Only the first occurrence is used by the browser.
**Why it happens:** Astro renders all three course panels to HTML simultaneously — IDs must be globally unique.
**How to avoid:** Use `id="crown-{course}-{skill.id}"` and reference `url(#crown-${course}-${skill.id})` in the ellipse fill. The frontmatter `treesData` loop already has access to both course and skill id.
**Warning signs:** Crown glow color is correct for B trees but wrong/missing for C and D trees.

### Pitfall 3: Progress bar and tree-progress selectors collide
**What goes wrong:** `[data-tree-progress="hora"]` and `[data-progress-bar="hora"]` exist 3 times each (one per course panel). `document.querySelector` returns the first match.
**Why it happens:** Same selector pattern used across panels without scoping.
**How to avoid:** Either scope selectors to `#tree-panel-${course}` container, or add `data-course` attribute: `data-tree-progress="${course}-${skill.id}"`. The second approach lets `updateProgress(course, skillId)` use a global query without traversal.
**Warning signs:** Checking a Kurs C goal updates the Kurs B progress bar.

### Pitfall 4: Leaf animation delay accumulation
**What goes wrong:** `bobDelay` is computed as `(i * 0.4).toFixed(1)s` per tree. With 18 trees sharing the same page, the delay values are fine (per-tree relative), but if 18 trees animate simultaneously on page load, there is a visible performance impact on low-end mobile devices.
**Why it happens:** All panels render their CSS animations on load, even when hidden with `display:none` / `visibility:hidden`. `class="hidden"` in Tailwind sets `display: none`, which suspends animations — this is actually safe.
**How to avoid:** Confirm that hidden panels' leaf animations are paused. Tailwind's `hidden` class (`display: none`) stops CSS animations. No action needed, but worth verifying on device.
**Warning signs:** Page feels sluggish on first load on mobile.

### Pitfall 5: Tab nav on trad.astro conflicts with index.astro TabNav
**What goes wrong:** Using the `TabNav.astro` component on trad.astro would render the 5-tab nav (B, C, D, Min plan, Resurser) and its script would conflict with the tree page's own tab-switching JS — `document.querySelectorAll('.course-tab')` would match all tabs.
**Why it happens:** `TabNav.astro` renders buttons with `class="course-tab"` that the inline script in `index.astro` targets. If reused on trad.astro the selector conflict would cause both scripts to fight over the same elements.
**How to avoid:** Use a separate, minimal tab nav specific to the tree page, with different CSS class names (e.g., `tree-tab` instead of `course-tab`). Do NOT reuse TabNav.astro in trad.astro.

### Pitfall 6: `define:vars` only serializes plain objects
**What goes wrong:** Passing complex nested objects in `define:vars={{ ... }}` that contain non-serializable values (functions, class instances) causes a build error or runtime `undefined`.
**Why it happens:** Astro serializes `define:vars` values as JSON. The existing pattern passes `skillsClient` (array of plain objects) and `goalTexts` (plain Record) — these are safe.
**How to avoid:** For multi-course, pass an object like `define:vars={{ skillsByCourseParsed, goalTextsByCourseParsed }}` where both are plain JSON-serializable objects. Keep the same structure, just nest by course key.

### Computed SVG Trunk Path (parameterized)

[VERIFIED: trad.astro lines 278-283]

Current hardcoded trunk (cx=150, half-width ~9):
```svg
d="M141,299 C138,267 136,232 139,202 C142,187 146,177 150,172 C154,177 158,187 161,202 C164,232 162,267 159,299 Z"
```

The left edge is `cx - 9 = 141`, right edge is `cx + 9 = 159`. To parameterize by tier, derive the path from `cx` and `trunkWidthHalf`:

```typescript
function trunkPath(cx: number, tier: TierParams) {
  const w = tier.trunkWidthHalf;
  const baseY = 299;
  const topY = 172;
  return `M${cx-w},${baseY} C${cx-w-3},267 ${cx-w-5},232 ${cx-w-2},202 `
       + `C${cx-3},187 ${cx-4},177 ${cx},${topY} `
       + `C${cx+4},177 ${cx+3},187 ${cx+w+2},202 `
       + `C${cx+w+5},232 ${cx+w+3},267 ${cx+w},${baseY} Z`;
}
```

Recommended approach: keep the SVG path as a literal string per tier (more readable for SVG), rather than computed. Define three literal trunk path strings in the `TIERS` object.

### computePositions with Tier Parameters

[VERIFIED: trad.astro lines 66-98]

Current function signature: `computePositions(n: number)` with hardcoded radii.

Extended signature:
```typescript
function computePositions(n: number, tier: TierParams) {
  const cx = 150, cy = 170;
  const { innerOrbit, outerOrbit, innerArcStart, innerArcEnd,
          outerArcStart, outerArcEnd, singleArcStart, singleArcEnd } = tier;

  if (n <= 6) {
    return distributeArc(n, cx, cy, innerOrbit + 35, singleArcStart, singleArcEnd);
    // (innerOrbit+35 approximates the current r=90 for medium tier)
  } else {
    const inner = Math.floor(n / 2);
    const outer = n - inner;
    return [
      ...distributeArc(inner, cx, cy, innerOrbit, innerArcStart, innerArcEnd),
      ...distributeArc(outer, cx, cy, outerOrbit, outerArcStart, outerArcEnd),
    ];
  }
}
```

### Tab Switching for Tree Page

Pattern ported from index.astro, using `tree-tab` class to avoid conflict:

```javascript
const treeTabs = document.querySelectorAll('.tree-tab');
const treePanels = document.querySelectorAll('.course-tree-panel');

const treeTabColors = {
  B: { border: 'border-cyan-600',   text: 'text-cyan-700'   },
  C: { border: 'border-violet-600', text: 'text-violet-700' },
  D: { border: 'border-rose-600',   text: 'text-rose-700'   },
};

function switchTreeTab(course) {
  treePanels.forEach(p => p.classList.toggle('hidden', p.id !== `tree-panel-${course}`));
  treeTabs.forEach(t => {
    const isActive = t.dataset.course === course;
    Object.values(treeTabColors).forEach(c => t.classList.remove(c.border, c.text));
    t.classList.remove('border-transparent', 'text-gray-400');
    if (isActive) {
      t.classList.add(treeTabColors[course].border, treeTabColors[course].text);
    } else {
      t.classList.add('border-transparent', 'text-gray-400');
    }
  });
}
```
