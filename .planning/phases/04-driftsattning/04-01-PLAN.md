<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub -> Netlify | Build pipeline trusts repo content |
| Teacher -> GitHub | Teacher edits JSON files via web UI |
| Browser -> Static site | Client loads static HTML/JS/CSS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | JSON data files | accept | Teacher has write access by design. JSON is validated at build time by Astro import -- malformed JSON breaks the build (fails safe). No user-generated content reaches other users. |
| T-04-02 | Information Disclosure | localStorage | accept | Checkbox state is non-sensitive (which goals a student checked). No PII stored. localStorage is per-device, not shared. |
| T-04-03 | Denial of Service | Netlify build | accept | Free tier has build limits but sufficient for a low-traffic educational site. Malformed JSON fails the build but does not affect the live site (Netlify keeps last successful deploy). |
| T-04-04 | Elevation of Privilege | GitHub repo access | mitigate | Only authorized collaborators can push to the repo. Verify teacher has appropriate access level (write, not admin). Branch protection on main is optional but recommended as future improvement. |
</threat_model>
